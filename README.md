## 环境

- Windows 11（原生，无 NVIDIA GPU → Ollama 路径）
- Python 3.12.15（uv 托管）+ 根目录 `ch2` extra（120 包）
- Ollama 0.40.4 + qwen3:0.6b（522 MB，App 与模型均落盘 D 盘，全本地推理）
- API 备用 provider：Kimi / DeepSeek（本机网络/key 原因最终未用于收尾实验，过程见心得 6.7~6.8）

## 核心收获

> 上下文工程回答的是一个问题：**怎样以更低成本，向模型提供一个信息充分的 c_t？**

- 无状态 API → 每一轮都在"重新喂养"模型，构造 c_t 的质量决定 Agent 的下限
- 顺序即成本：仅打乱工具顺序，KV 缓存占比 33%→3.4%、平均 TTFT 5.7s→11.1s（实验 2-3）
- 小上下文时压缩反而膨胀（127.7%），上下文感知策略让总耗时减半（实验 2-10）
- 0.6B 小模型也能正确产出工具调用 JSON——工具调用行为主要由上下文结构驱动（实验 2-1）
- 模型选型是实验设计的一部分：太强/太弱都会抹平注入防御的教学对比曲线（实验 2-5）
